davinci-resolve-mcp 4.19.3 — loopback Tailscale Serve Host/Origin fix
================================================================

Applies to an installed 4.19.3 tree. One file: src/utils/mcp_transport.py.
Does not change Resolve projects, timelines, databases, media, or Tailscale
Funnel. Leave DAVINCI_MCP_HOST=127.0.0.1. Do not bind 100.80.148.53 or any
other non-loopback address.

If dry-run fails, do not force it. Restore is unnecessary because dry-run
does not write. The installed file is not the 4.19.3 original this patch
was built from.

Rollback
--------
  patch -R -p1 --dry-run < docs/patches/4.19.3-tailscale-serve-host.patch
  patch -R -p1 < docs/patches/4.19.3-tailscale-serve-host.patch

Or, at any time:

  cp -p src/utils/mcp_transport.py.bak-4.19.3 src/utils/mcp_transport.py

Restart only the networked MCP process afterwards. Do not quit Resolve.

Restart
-------
Stop the process that was started as `src/server.py --transport streamable-http`
(or `sse`) the same way it was started, then start it again with the same
command and the same environment:

  DAVINCI_MCP_HOST=127.0.0.1
  DAVINCI_MCP_ALLOWED_HOSTS=macbook-pro.tailfacc7e.ts.net
  DAVINCI_MCP_TOKEN=<the token you already use>

The value is the hostname only. `*` is ignored. A URL is ignored.

After restart, logs/server.log should contain a line:

  MCP transport Host allowlist:

and that line should include macbook-pro.tailfacc7e.ts.net and 127.0.0.1:*.
The 4.19.3 process did not log an allowlist for a loopback bind.

is not forwarding that hostname to this process.

What stayed the same
--------------------
- Bind stays 127.0.0.1. Bearer is still required on every request (401 first).
- With DAVINCI_MCP_ALLOWED_HOSTS unset, loopback still allows only loopback.
- A different Host is 421. A different Origin is 403.
- stdio is unchanged. The control panel's own Host gate is unchanged.
